# 资源默认值与配置迁移

客户端优先使用已保存的用户值，没有保存值时使用当前资源默认值。
保存值等于当前默认值时会移除该值，之后随资源默认值更新。
因此，手动选回默认值也表示重新跟随；客户端不能从旧配置中还原用户是否曾经手动修改。
旧值等于历史默认、但不同于当前默认时仍保留，不会猜测历史默认。

单选和开关按 case 名称保存，保留派生 index 供旧客户端读取。
旧配置仅有 index 时只能按当前资源解释；首次迁移时若资源同时重排 cases，
请核对选择是否符合预期。已删除的单选项会要求重新选择。
复选项里暂时不存在的 case 仍保留，避免后续恢复该 case 时丢失原选择。

任务按 name 匹配。资源中缺失的任务先标记不可用，下次启动仍缺失时才移除；
大量任务同时缺失时暂停自动清理。主动删除和主动清空的队列分别记录，不会自动补满。

首次任务状态迁移保留同目录 `.before-task-state-v1.bak` 备份；
背景迁移保留 `.before-background-defaults-v1.bak` 备份。
恢复前退出所有客户端进程，另存当前配置，再将对应备份复制回原配置路径。
资源定义也应与待恢复配置配套；相同资源与新客户端再次启动时仍会执行适用的迁移。

外部 Agent 不应把实例 JSON 中缺少的值当作空值：需要按 interface 定义补齐默认值。
直接读取配置文件的资源应在启用此客户端前更新 Agent。
退回旧客户端可能重新写入默认值，使跟随状态丢失；建议回退前备份整个 config 目录。

默认背景改动写在模板顶层；曾发布过的旧模板原样加入 `LegacyTemplates`，
供客户端识别已复制进用户配置的旧默认。等值识别无法区分用户主动选中的相同背景，
因此迁移保留备份。主题和 preset 的实时跟随不属于本次迁移范围。
