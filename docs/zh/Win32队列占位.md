# Win32 队列占位

Windows Win32 控制器在连续执行任务时使用内部占位任务，避免任务边界触发
MaaFramework inactive，导致伪最小化窗口反复恢复。环境变量 `MFAA_QUEUE_HOLD=0`
（也接受 `false`、`off`）可关闭此行为。

首个真实任务之前会先投递占位；后续按真实任务、新占位、释放旧占位的顺序推进。
占位持续到显式放行、停止或实例释放，长时间等待不会自行释放。
进入模态等待或非 MaaFramework 任务前会放行；收尾等待失败会停止 Tasker，
不会继续按成功完成处理。

资源 Agent 的任务事件也会看到占位。内部 entry 以 `MFAA_QueueHold_` 开头，
后接本次进程的随机标识；内部动作以 `MFAA_QueueHoldAction_` 开头。
资源若在每次任务开始时执行准备操作，应跳过这些内部 entry，不能仅匹配旧的
固定名称 `MFAA_QueueHold`。MFAA 自身只过滤精确匹配的内部名称，资源中的同名旧节点
仍保留回调。占位可能在真正任务前后各出现一次，不代表用户任务执行次数。
